# 04：在 Host 合并并缓存用量请求

- 状态：已采纳
- 适用范围：`createUsageService()` 的并发、缓存和取消行为

## 背景

侧栏、设置页和手动刷新可能在相近时间发出请求。每个独立调用都读取用量会增加上游请求，并使同一时间段内的显示不一致。

## 决策

Host 的 `createUsageService()` 合并并发请求，并缓存完成结果。默认成功缓存 60 秒；失败结果最多缓存 10 秒，且不会超过 `cacheMs`。配置允许 `cacheMs` 为 0–600000 毫秒。带 `?refresh=1` 的请求跳过有效缓存，但仍与正在运行的查询共享结果。

每个 HTTP 调用方可取消自己的等待；单个调用方断开不会取消所有调用者共享的上游查询。服务卸载时中止自有请求并等待其结束。登录开始、登录状态变为已认证及退出登录时清除额度缓存。

## 后果

- 强制刷新仍受并发合并影响；它不是并行创建第二个上游请求。
- 调整缓存或取消语义时，必须同时检查用户断开、共享请求、登录切换和插件卸载路径。
- 成功与失败缓存时长由 Host 控制；Client 的刷新周期不等同于上游请求的实际频率。
