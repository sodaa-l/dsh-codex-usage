# 06：本地配置刷新周期并保留最后成功数据

- 状态：已采纳
- 适用范围：Client 自动刷新、故障恢复和浏览器偏好

## 背景

用户需要可控的刷新频率，也需要独立选择侧栏和底栏显示哪些用量。暂时的网络错误不应立即清空已有额度；多个入口的快照和刷新时刻必须一致，且额度重置时应立即查询，不能等待下一次周期刷新。

## 决策

刷新周期、侧栏及底栏各自的总开关和两种窗口子开关仅保存在当前浏览器的 `localStorage`，默认开启，侧栏与底栏互不影响。两个总开关关闭时均禁用所属子开关并保留选择；旧底栏设置缺少总开关字段时按开启处理。刷新周期可选 1、5、15、30 分钟，默认 1 分钟。相同页面通过自定义事件同步设置，同一来源的其他标签页通过 `storage` 事件重新读取。

每个 Client 模块只创建一份用量 store，侧栏、底栏、设置页和多个会话通过 `useSyncExternalStore` 订阅同一快照。首个可见入口挂载时读取；至少一个侧栏/底栏入口可见时只运行一个周期定时器，修改周期只调整该定时器。手动刷新和登录成功直接刷新 store，不再广播事件引起各入口重复请求。隐藏或卸载入口只释放该入口的需求；最后一个自动刷新入口消失后停止周期轮询，最后一个用量入口消失后中止请求并清理所有计时器。

store 根据两个窗口的 `resetsAt` 安排额外定时器，到期强制查询以跳过 Host 缓存。同一时间到期的窗口合并刷新；周期强刷恰好在重置时间开始时不再重复查询。若重置发生于旧请求进行期间，则排队在旧请求结束后强刷，避免 Host 并发合并返回重置前的查询结果。每个窗口的同一重置时间只触发一次，服务仍返回旧时间时不循环请求；识别到新重置时间后重新调度。

Client 请求遇到可重试错误时最多尝试三次，首次后等待 1 秒，第二次后等待 3 秒。若失败但此前有成功窗口，则继续显示最后成功的窗口数据；未登录状态会显示未登录结果，不保留旧额度。最后一个入口消失或插件卸载时清除相关请求与计时器。

## 后果

- 刷新周期和显示开关不在不同浏览器间同步，且没有云端保存。关闭侧栏总开关后仅释放侧栏需求，底栏仍可继续共享刷新；所有自动刷新入口消失后不再周期查询。
- 旧额度可能在服务暂时不可用时继续显示；内部状态会标记为 stale，但界面按产品决定不显示额外的 stale 警告。
- 设置页依据本地账户资料、OAuth 登录完成状态或成功的额度响应显示连接状态与退出入口；额度不可用或认证状态查询失败不应抹掉已知账户。认证操作失败显示对应错误并允许重试，短暂轮询失败继续查询。成功退出后立即清空共享额度并同步所有入口，忽略退出或取消前发出的迟到认证/用量响应。
- 调整刷新与重置调度时，应验证多入口同步、迟挂载、并发请求、同时重置、过期时间去重、取消、连续失败恢复、偏好同步、退出登录和插件卸载。
