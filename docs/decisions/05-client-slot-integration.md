# 05：在实际声明的 Client 子插槽注册 UI

- 状态：已采纳
- 适用范围：侧栏卡片、设置页与 Client 生命周期

## 背景

DSH 侧栏及设置页插槽由 Client 逐步声明。等待父插槽存在不保证其子插槽已经可注册；过早注册会导致 UI 在启动时缺失。

## 决策

`client.js` 分别等待 `sidebar.footer.action` 和 `settings.section` 这两个目标插槽本身声明后，再注册卡片和设置区。包清单将 Client 声明为 Web 平台的立即加载模块，并注入 sidebar 与 locale 服务。侧栏卡片使用顺序 `-1000`，设置区使用顺序 `35`。

卡片采用透明背景、DSH 字体与主题色。当前全宽布局使用局部 `:has()` 选择器适配侧栏插槽生成的包装层。

## 后果

- 不要将等待目标改为父级 `sidebar` 或 `sidebar.settings`；父级可能先于实际目标子插槽出现。
- 插槽名称、声明顺序、包装层 DOM 或排序约定改变时，需要在真实 DSH 界面验证，而不只依赖组件单元测试。
- CSS 的 `:has()` 全宽规则与当前插槽 DOM 有耦合；若 DSH 调整结构，应同步检查卡片宽度、横向溢出和窄侧栏样式。
